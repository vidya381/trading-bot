### 1. The decision: mechanism F, and six things deliberately not adopted

An investigation session (below) enumerated the available mechanisms for
injecting build identity without choosing among them. The operator chose
**mechanism F: Cloudflare's own per-deploy version id.**

The reason it was chosen is the one property none of the alternatives have:
**it is the only signal in the enumeration that is not self-reported by the
artifact under examination.** Every field `/health` can return — a version, a
SHA, a timestamp — is a literal captured from the deploying machine and recited
back by the bundle. The platform mints the version id per upload, and the
artifact can neither forge it nor restate it.

**Recorded as OPEN DECISIONS, deferred deliberately, not oversights:**

| not adopted | status |
| --- | --- |
| Bumping `package.json` per deploy (§16) | **Open.** Never done in 90 commits; explicitly not started now |
| Tagging the deploy commit (§16) | **Open.** Zero tags exist in the repository |
| Injecting a git SHA at build time | **Open.** Rejected for this step; it is a claim about the deploying machine's HEAD, not about the bundled bytes |
| A tree-cleanliness deploy gate | **Open.** Would be what makes a SHA mean something; also blocks deploying an uncommitted tree, which is a workflow decision, not a technical one |
| `audit_log` deploy entries (§16) | **Open and UNIMPLEMENTED.** No writer exists anywhere in the repository |
| CI (§15, §16.1 steps 3–5) | **Open and UNBUILT.** No `.github/` directory exists |

Recording the version id per deploy is the **operator's process, not code**. No
tooling was built for it and none is proposed here.

### 4. ⚠ The correction the coding session had to make against itself

**The investigation session wrote that the old test "can never detect
staleness". A control run disproved that, and the correction is kept here rather
than quietly dropped.**

Mutating the handler to return a hardcoded `"9.9.9"` was caught by the **old
circular test too**. The old test compared the response against `package.json`'s
value; a handler that stops forwarding `package.json` diverges from it and
fails. The circularity was never total.

The blind spot is **exactly one case**:

| mutation | old (circular) test | new (literal) test |
| --- | --- | --- |
| handler stops forwarding `package.json` | **catches** | **catches** |
| handler drops or renames `version` | **catches** | **catches** |
| **`package.json`'s version changes** | **passes — blind** | **fails** |

Expected and actual read the same file in the same build, so under a version
change they **move together**. That single case is the entire gain from this
step's test change.

**And under mechanism F that value is frozen by decision** — the version bump
was explicitly not adopted. So what was built is a **freeze alarm on a constant
that is supposed to never move**, not a safety improvement. It is worth having
and it is small, and describing it as anything more would be false.

#### ⚠ `d00e16ed…` is a Cloudflare version UUID, NOT a git SHA

Entry 52 records it in a bare lowercase-hex format that reads exactly like the
git SHAs used everywhere else in this log. **They are different kinds of
identifier and they resolve against different systems.** A Cloudflare version id
is minted per upload and means nothing to `git show`; a git SHA means nothing to
`wrangler`. Flagged here so a later reader does not attempt to check one out, or
quote one as the other — the same conflation entry 36 recorded when a git SHA
was reported as if it identified a deployed build.
