# 78 — A market price for halted bots (Option B), and the label that makes the frozen one honest

**NOT COMMITTED.** Ten files on disk (seven modified, three new), plus this entry
and its README row; `HEAD` is **`eab337e`** ("Fix resume's split-brain window and
add emergency-sweep coverage for it" — entry 77's work, committed since).

**The split held.** No `wrangler`, no deploy, no HTTP call, no query against real
D1, no browser, and nothing done to any live bot.

**What this closes.** The operator's original request from earlier tonight: *see
a real, current market price on a halted bot, to decide whether to resume,
without checking an exchange elsewhere.* The investigation that produced it
enumerated four options and chose none:

| | Option | Outcome |
| --- | --- | --- |
| **A** | Keep every halted bot subscribed to the full live feed | Not chosen. Pins the pair's `PriceFeed` object and its outbound socket alive indefinitely (it cannot hibernate while connected) for a bot that is not trading, and requires relaxing the `status === "running"` guard that makes "not running ⇒ takes no action" true by construction. |
| **B** | A lightweight PERIODIC fetch, not a subscription | **CHOSEN by the operator before this build. This entry is that build.** |
| **C** | Serve it from the `PriceFeed` Durable Object's in-memory candle | Not chosen. Cheapest when a pair has running bots; useless exactly when every bot on the pair is halted, which is the case this is for. |
| **D** | Fetch it in the dashboard at render time | Not chosen. No venue-credential path from the browser, and the CSP story was unexamined. |

## PART 1 — WHAT WAS BUILT, AND THE TWO THINGS THAT MAKE IT HONEST

**The feature.** A bot that is `halted`, **not** archived, **not** stopped and
**not** created now shows a separate **MARKET PRICE** tile on its detail page,
fetched from the venue while that page is open, carrying its own **`as of
HH:MM:SS`**.

**The second half, and it matters as much as the first.** The bot's own
**CURRENT PRICE** tile — `state.lastPrice`, correctly frozen at the instant the
bot halted — is no longer rendered as a bare number. On a halted bot it now
reads **`frozen at halt · HH:MM:SS`**.

**Why that is not cosmetic.** The investigation that started all of this began
with a real bot, `bot-ri6iml`, whose price appeared "stuck" across several
checks. It was not stuck. It was **correct**: a halted bot unsubscribes from its
feed, and `#checkPriceFreshness` states outright that *"a halted bot's clock is
frozen BY DESIGN"*. What made a by-design value look like a defect was that it
was displayed as a number with no account of itself, next to other numbers that
were live. Adding a second, genuinely-live price beside it without labelling the
first would have made that **worse**, not better — two numbers disagreeing, with
nothing on screen saying why.

So both tiles now carry their own explanation. One says where the market is and
when it was read; the other says what it is and when it stopped moving.

## PART 2 — ISOLATION, PROVEN RATHER THAN ASSUMED

The value **never enters `BotRuntimeState`**, is **never persisted to Durable
Object storage**, and is **assembled fresh per API request** in the serialization
layer. It travels from the venue to the screen and nowhere else.

The structural reason it cannot influence a trade: the strategies do not read
`lastPrice` — or any stored price — at all. `decide()` and `gridDecide()` take
the price as an **argument**, handed to them by `#onPriceUpdatePass` from the
bot's own feed. There is no seam through which an API-layer field could reach
them.

**That was PROVEN, not asserted.** `market-price-isolation.test.ts` is a source
scan, in the shape `src/db/no-raw-d1.test.ts` established, because the property
is an **absence** — and no behavioural test can pin an absence. Someone could add
a read of the field inside `gridDecide` tomorrow and every behavioural test in
the repository would still pass.

**And the guard was checked for vacuity, because a source scan that matches
nothing passes for the wrong reason.** `marketPrice` was deliberately injected
into `src/strategies/grid.ts` and `dashboard/src/derive.ts`, and **3 of the 5
tests correctly failed** against that injection. The probe was then reverted and
all 5 pass again. The guard is real.

## PART 3 — TWO CORRECTIONS TO THE BUILD BRIEF, FOUND BY MEASURING

Both are recorded as corrections, not footnotes.

### 1. The integration point is NOT rate-limited by this system

The brief described `getCurrentPrice` as *"cheap against rate limits"*, which
carried an assumption that this path shares the bot's budgeted request path.
**Checked against source: FALSE.** `clientForAccount` returns a raw
`RestExchangeClient`; `withRateLimit` is never applied on the API path. The
section 5.4 `RateLimiter` Durable Object, the 1200-weight-per-minute ceiling and
the weight-2 figure for `tickerPrice` all describe the **bot's** gated path and
have no bearing here. The existing `/symbols` and `/candles` endpoints are
ungated in exactly the same way; this is not a new hole, but it is not the
protection the brief assumed either.

### 2. The cost estimate was wrong by roughly 12×

The earlier investigation estimated *"one halted bot polled every 60s = weight 2
per minute out of 1200"* and called it trivially small. The measured figure:
`usePolling`'s `POLL_INTERVAL_MS` is **5000 ms**, and the detail page uses the
default. So the real cost is:

> **12 requests per minute while a halted bot's detail page is actually open,
> and ZERO the instant the operator navigates away.**

It does not scale with fleet size and there is no background component. **In
absolute terms this is still small** — but it is reported at its measured number
rather than at the smaller estimate, because the estimate was the thing being
checked.

⚠ **This is FLAGGED, NOT CLOSED.** No documented Gemini public rate-limit ceiling
exists anywhere in this repository to check 12/min against. Nothing here asserts
one from memory. It is left as something the operator can confirm against
Gemini's own documentation, and is **not** treated as a blocking risk.

## PART 4 — A SMALLER INTEGRATION THAN THE ONE ASKED FOR

The brief allowed for a new endpoint. **One was not needed.**

`BotDetail.tsx` already polls `GET /api/bots/:id` through `usePolling`. Extending
that response with the market price gave the whole feature with:

- **zero new polling code**,
- **zero changes to `usePolling`** — which is on the standing do-not-touch list,
  so the smaller integration is also the one that respects that constraint,
- **zero new fetch wiring** in the dashboard.

It also fires only while a human is on that page, which is precisely the
"on-demand, no ongoing cost" property Option B was chosen for — obtained from the
existing poll rather than from new machinery.

**`listBots` was deliberately left untouched.** Fetching per row would turn one
screen into one venue call per halted bot per tick, which is the shape Option B
exists to avoid.

**The brief also anticipated per-pair deduplication. It is unnecessary.** The
detail route renders exactly one bot at a time, so there is no fan-out to dedupe
— one page, one pair, one call per tick.

## PART 5 — VERIFICATION

### `market-price.test.ts` — 6 tests, the fetch gate and the timestamp

1. `is populated for a halted, unarchived bot`
2. `is NOT fetched for created, running, stopped, or archived bots` — and the
   assertion is that **the venue was never reached**, not merely that the field
   came back absent. A recording lister proves the call did not happen. Archived
   is tested at status `halted`, so the status alone would qualify it and the
   flag is what excludes it.
3. `is null, not an error, when the venue cannot be reached` — the venue **was**
   reached and refused, and the detail view still answers.
4. `is present and carries the fetch time, not the bot's frozen one` — asserts
   the timestamp equals the fetch time **and** is provably distinct from the
   frozen price's own `lastPriceAt`.
5. `travels with the price through the serializer, on the detail shape` — and
   asserts `lastPrice` stayed null rather than borrowing the market's number.
6. `defaults to null on the serializer, so an un-fetched bot renders nothing`

### `market-price-isolation.test.ts` — 5 structural tests

1. `is named nowhere outside the API assembly layer and its fetcher`
2. `is absent from the strategies, which decide what to trade` — `grid.ts` and
   `dca.ts` named individually rather than swept, so deleting one cannot quietly
   empty the assertion.
3. `is absent from the Durable Object that holds state and places orders`
4. `does not appear in BotRuntimeState, so it can never be persisted` — the
   narrowest and most important of the five, **with a counter-assertion that
   `lastPrice` and `lastPriceAt` are still present**, so the guard cannot pass by
   the interface having been renamed away underneath it.
5. `is not read by the dashboard's PnL or ladder maths` — `derive.ts`,
   `accountTotals.ts`, `GridLadderView.tsx`.

### A test flaw this session caught in its own work

The first version of `market-price.test.ts` **re-stated the gate**
(`archived || status !== "halted"`) as a local helper instead of exercising the
real one. That is a second implementation of the safety property, free to drift
from the first — the exact failure entry 44 names, written into the test that
exists to protect against it. **Fixed by exporting `marketPriceFor` from
`handlers.ts` and testing the real function**, with the export carrying a comment
saying why it is exported. The gate is now tested or nothing is.
